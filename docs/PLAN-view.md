# 視点変更プラン：自機中心・前方固定・広いフィールド

## 1. 要件

| # | 要件 | 対応方針 |
|---|------|----------|
| V1 | 自機を画面の中心にし、上を前方に固定する | カメラを自機の位置と向きに追従させ、世界の側を回転させて描く（自機は常に画面中央で上向き） |
| V2 | 画面は正方形 | 表示領域を正方形にし、余白は黒で埋める（縦長スマホでは上下、横長PCでは左右に余白） |
| V3 | 実際のフィールドは画面の4倍 | 見えている範囲より広いフィールドにする（「4倍」の解釈は §7 で確認） |
| V4 | 弾の射程は画面の見えている範囲 | 撃った位置から画面の上端まで（＝画面の一辺の半分）届いたら消える |
| V5 | 背景に暗いドットの星を表示し、自機の移動を分かりやすくする | フィールドに固定した星を描き、自機が動くと星が流れて見えるようにする |

## 2. 用語と寸法（案）

- **画面（ビュー）**：一辺 `VIEW = 800` の正方形（論理単位。実際の表示サイズに合わせて拡縮）
- **フィールド**：一辺 `FIELD = 1600`（面積が画面の4倍）
- **弾の射程**：`VIEW / 2 = 400`。弾の速さを保つなら、寿命を `400 / 弾速` 秒にする
- フィールドは今と同じく端がつながる（上下左右ループ）

## 3. 設計

### 3.1 描画（カメラ）
- **座標変換**：画面中心へ移動 → 自機の向きの逆に回転（前方が上になるよう −(角度 + 90°)）→ 自機の位置の逆に移動、の順で世界を描く
- **端のループ**：フィールドの端をまたぐ物体は、自機から見て最も近い位置（差分をフィールド幅で折り返した位置）に描く。今の「端の反対側にも描く」処理を置き換える
- **画面外の省略**：画面の対角線の半分（約566）＋物体の半径より遠い物体は描かない
- **自機がいないとき**（撃破されて復活待ち）：カメラは撃破された位置と向きで止め、復活したら新しい位置へ切り替える
- **表示の外周**：正方形の外は黒で塗り、HUD（得点・残り時間）は回転しない層で正方形の内側の上部に重ねる

### 3.2 背景の星
- フィールドに固定した暗いドットを、シード付き乱数で決まった位置に配置する（全員が同じ星空を見る。通信は不要）
- 密度は画面あたり約150個を目安にする。明るさは2〜3段階の暗いグレーにする
- 星もフィールドの端でループし、世界と一緒に回転する。これで、前進すると星が下へ流れ、旋回すると星が回って見える
- 奥行き感を出す「視差（遠い星ほどゆっくり動く）」は任意（§7）。入れる場合、遠い層の星はフィールドに固定されなくなる

### 3.3 ゲームのルール（シミュレーション）
- **ワールドサイズの変更**：`WORLD_W / WORLD_H`（現在 1280×720）を `FIELD`×`FIELD` に変える。定数はすべて `constants.ts` にまとまっていて、参照箇所は約40か所ある
- **弾**：射程を §2 のとおりにする。UFOの弾も同じ射程にする
- **小惑星の数**：フィールドが広くなると密度が下がる。面積に比例して増やすか、今の数のままかは §7 で確認
- **出現位置**：対戦の出現地点をフィールドの広さに合わせて配置し直す。小惑星は「どの船からも画面の外（半径約600以上）」に出す
- **UFO**：フィールドを横切るのにかかる時間が延びるので、速さか出現範囲を調整する（例：誰かの画面の近くに出す）
- **ハイパースペース**：フィールド全体のランダムな位置へ飛ぶ（変更なし）

### 3.4 他のプレイヤー・物体の位置を知る手段（推奨）
フィールドが画面より広いと、相手がどこにいるか分からなくなる。次のどちらか（または両方）を入れることを推奨する（§7）。
- **画面端の矢印**：画面外にいるプレイヤー（とUFO）の方向に、その色の小さな矢印を出す
- **レーダー**：画面の隅に、フィールド全体を縮小した小さな地図を出す（自機を中心・前方を上にして回転）

### 3.5 通信
- スナップショットの形式は今のままでよい（全員に全物体を送る）
- 小惑星が増えると1回あたりのデータが大きくなる。今の上限の目安（16KB）に収まるかをテストで確認し、超えるなら各プレイヤーの近くの物体だけを送るよう最適化する
- ゲスト側のカメラは、補間済みの自機の位置と向きを使う（今の補間処理はそのまま使える）

### 3.6 操作・画面レイアウト
- 操作方法は変えない（回転ボタン＝自機が回ると世界が逆に回って見える）
- 正方形の画面は縦長スマホに収まりやすい。縦持ちでは正方形の下の余白にタッチボタンを置けるので、「横向き推奨」の表示は外す
- 横長のPC・スマホでは、正方形の左右の余白にタッチボタンを置く

## 4. 実装ステップ

| # | 内容 | 完了条件 |
|---|------|----------|
| 1 | 定数の整理（`VIEW`、`FIELD`、弾の射程）とシミュレーションの対応（出現位置、小惑星数、UFO） | 単体テストが新しいフィールドサイズで通る |
| 2 | カメラ描画（自機中心・前方固定・正方形・端のループ・画面外の省略） | ソロで自機が中央上向き、世界が回転・移動して見える |
| 3 | 背景の星 | 前進・旋回で星が流れ、動きが分かる |
| 4 | 画面外の相手の表示（矢印／レーダー） | 画面外の相手の方向が分かる |
| 5 | レイアウト調整（正方形＋タッチボタン配置、HUD） | PC・スマホ縦横で操作できる |
| 6 | 通信量の確認・必要なら最適化、実機での対戦確認 | 4人対戦でスナップショットが上限内、実機で動く |

## 5. テスト方針
- **単体テスト**：弾が射程（VIEW/2）で消える、端をまたいだ衝突、出現位置が画面外になる、スナップショットの大きさ
- **ブラウザでの確認**：スクリーンショットで、自機が中央上向きであること、旋回すると世界が回ること、星が表示されること
- **実機**：スマホの縦持ち・横持ちでの操作性、描画の重さ（小惑星と星が増えるため）

## 6. リスク
| リスク | 影響 | 対策 |
|--------|------|------|
| 世界が回転する視点は酔いやすい人がいる | 遊びにくい | 実機で確認し、必要なら回転を少し滑らかにする設定を検討 |
| 描画する物体（星・小惑星）が増えてスマホで重くなる | カクつく | 画面外の省略、星をまとめて描く（1回のパス） |
| 広いフィールドで相手に出会わない | 対戦がつまらない | 矢印／レーダー、フィールドの広さや小惑星数の調整 |

## 7. 決定事項
1. フィールドは画面の**面積4倍**（一辺2倍）：VIEW=800、FIELD=1600
2. フィールドの端は**反対側につながる**（ループ）
3. 小惑星の数は**約2倍**に増やす（1ウェーブの上限も2倍）
4. 相手プレイヤーの位置は**レーダー**で分かるようにする（画面端の矢印はなし）
5. 背景の星は**1層**（フィールドに固定）

## 8. 実装状況
- 実装済み：フィールド 1600×1600（画面 800 の面積4倍・端はループ）、弾の射程 400（UFOの弾も同じ）、小惑星の数を2倍（1ウェーブ上限22）、小惑星は船から600以上離れた位置に出現、自機中心・前方固定のカメラ、正方形の画面、背景の星（1層・フィールド固定・約600個）、対戦時のレーダー（右下。相手プレイヤーの位置と、画面に見えている範囲を表示）
- 縦持ちスマホでは正方形を上寄せにし、音声・終了ボタンを上、タッチボタンを下に配置。「横向き推奨」の表示は削除
- 確認済み：単体テスト、ヘッドレスChromiumでのソロ・3人対戦・スマホ縦横の画面表示
- 未確認：実機での操作感（回転する視点の酔いやすさ）、描画の重さ、対戦のバランス（広さ・小惑星数）
